## Why

Currently the project relies on developers manually running `bun run lint` and `bun run build` before committing, as documented in CLAUDE.md. This is error-prone — as demonstrated when a recent file move introduced broken import paths that only surfaced during manual browser testing. Automating these checks via git hooks enforces them at the right moments without relying on memory.

## What Changes

- Add `simple-git-hooks` as a dev dependency for lightweight, zero-config git hook management
- Add a `pre-commit` hook that runs `bun run lint` — fast feedback on style/import-order issues before a commit is recorded
- Add a `pre-push` hook that runs `bun run build && bun test` — ensures the project compiles and all tests pass before code reaches the remote
- Add a `simple-git-hooks` configuration section to `package.json`
- Add a `postinstall` script to `package.json` to automatically register hooks after `bun install`

## Capabilities

### New Capabilities
- `git-hooks`: Automated pre-commit linting and pre-push build+test enforcement via simple-git-hooks

### Modified Capabilities

## Impact

- `package.json`: new dev dependency, `simple-git-hooks` config, `postinstall` script
- `.git/hooks/`: `pre-commit` and `pre-push` hook files generated by simple-git-hooks
- Developer workflow: lint failures block commits; build or test failures block pushes

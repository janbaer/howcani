# Review rules for howcani

## Release

- Do not change `version` in `package.json` and do not edit `CHANGELOG.md`. The merge step writes both after the review, and a `package.json` change on `main` triggers the image build and deploy.

## Dependencies

- Pin every dependency in `package.json` to an exact version: no `^`, `~` or ranges.
- When `@codemirror/state`, `@codemirror/view` or `@codemirror/language` changes in `dependencies`, set the matching entry in `overrides` to the same version in the same PR. `bun update` never touches `overrides`, and a stale pin leaves duplicate CodeMirror copies that break the editor.

## Database

- Never edit, renumber, rename or remove an existing entry in `MIGRATIONS_TEMPLATE` (`src/server/db/migrations.ts`). Schema changes go into a new migration with the next version number. Databases already past a version never run it again, and migration 7 is matched by its name.
- A migration that adds a table also adds it to `clearTestDatabase()` in `src/server/db/test-helpers.ts`.

## Server

- Mutation routes in `src/server/routes/` use the session-bound `session.itemService` / `session.tagService`, never the `itemService` / `tagService` singletons.
- Every new client-side route is also declared in the `routes` map in `src/server/index.ts`.
- New or changed behaviour in a service, repository or route under `src/server/` comes with a change to its co-located `*.spec.ts`.
- Service methods return `Result<T>` for expected failures instead of throwing, and routes map `error.code` to a status.
- Every `/api` error response has the shape `{ error: { code, message } }`.

## Config

- A new operator setting is added to `src/server/config/config.schema.ts` and `config.example.yaml` in the same PR.
- Secrets (API keys, tokens, `HOWCANI_JWT_SECRET`) are read from environment variables only, never added to the config schema or any YAML file.

## OpenSpec

- A PR that implements a change in `openspec/changes/<name>/` also archives it to `openspec/changes/archive/YYYY-MM-DD-<name>/` in the same PR.
